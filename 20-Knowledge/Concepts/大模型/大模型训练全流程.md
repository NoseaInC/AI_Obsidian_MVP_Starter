# 大模型训练全流程

> 关联笔记：[[大模型架构知识体系]]

---

## 总览

大模型训练 = **预训练（学知识）→ 监督微调（学对话）→ 对齐训练（学做人）→ 后训练整合（强化专项能力）**

---

## 阶段一：数据准备

### 1.1 数据收集与清洗
- **来源**：网页爬取（Common Crawl）、书籍、代码库（GitHub）、论文、维基百科等
- **清洗**：去重（MinHash / SimHash）、过滤低质内容、去除个人信息、语言分类
- **配比**：不同来源按比例混合（如 DeepSeek-V3 强调数学/代码比例更高）

### 1.2 Tokenization（分词）
- 将原始文本切成 token（子词单元）
- 主流方法：**BPE**（GPT 系列）、**SentencePiece**（LLaMA）、**BBPE**（字节级 BPE）
- 词汇表大小：通常 32K–256K tokens
- 这一步决定了模型"看到"的基本单位

---

## 阶段二：预训练（Pre-training）

### 核心目标
在海量无标注语料上进行**自监督学习**——给定前面的 token，预测下一个 token（Next Token Prediction / Causal Language Modeling）。

### 2.1 训练数据规模

| 模型 | 预训练数据量 |
|---|---|
| GPT-3 | ~300B tokens |
| LLaMA 3.1 | ~15T tokens |
| DeepSeek-V3 | ~14.8T tokens |
| DeepSeek-V4 | ~32T+ tokens |

趋势：数据量持续翻倍，高质量数据成为瓶颈。

### 2.2 训练目标

$$\mathcal{L} = -\sum_{t} \log P(x_t \mid x_{<t}; \theta)$$

即最大化每个位置正确预测下一 token 的概率。计算的是全部 token 位置的平均交叉熵损失。

### 2.3 分布式训练系统

当前标配是 **3D 混合并行**：

```
┌─────────────────────────────────────┐
│         3D 混合并行架构              │
│                                     │
│  数据并行 (DP/FSDP)                 │
│  ├─ 数据切分到数千 GPU              │
│  ├─ ZeRO-1: 优化器状态分片          │
│  ├─ ZeRO-2: +梯度分片               │
│  └─ ZeRO-3: +参数分片               │
│                                     │
│  张量并行 (TP)                      │
│  └─ 单层内矩阵乘法切分              │
│                                     │
│  流水线并行 (PP)                    │
│  └─ 不同层分到不同设备              │
│                                     │
│  三者叠加 = 万卡集群训练            │
└─────────────────────────────────────┘
```

典型配置（以 DeepSeek-V3 为例）：
- 2048 块 H800 GPU
- FP8 混合精度训练
- DualPipe 双向流水线（计算与通信几乎完全重叠）
- 总预训练成本：~2.66M GPU hours

### 2.4 优化器与精度

| 组件 | 2024-2025 主流 | 2026 新方向 |
|---|---|---|
| 优化器 | **AdamW**（β₁=0.9, β₂=0.95） | **Muon**（DeepSeek-V4 采用） |
| 精度 | BF16 / FP8 混合 | FP8 + **FP4** 混合（MoE expert 降到 FP4） |
| 学习率调度 | Cosine decay + warmup | 同，更长的 warmup |

### 2.5 Multi-Token Prediction (MTP)

DeepSeek-V3/V4 和 Gemma 4 的新范式：每个位置不仅预测下一个 token，还预测接下来 1~3 个 token。

- **收益**：训练信号更密集，样本效率更高
- **推理时复用**：MTP 模块可用作推测解码的 drafter，加速推理

---

## 阶段三：监督微调（SFT / Instruction Tuning）

### 核心目标
让模型从"会接话"变成"听得懂指令、答得对问题"。

### 3.1 数据格式
使用高质量的 **指令-回答对**（人工标注 + 合成数据）：

```json
{
  "instruction": "请解释什么是 Transformer",
  "input": "",
  "output": "Transformer 是 2017 年 Google 提出的..."
}
```

### 3.2 数据来源
- 人工标注（贵，但质量最高）
- 强模型蒸馏（用 GPT-4 / Claude 生成，量大但需去噪）
- Self-instruct / Evol-Instruct（模型自己生成指令变体）
- 专项领域数据（数学 CoT、代码、工具调用）

### 3.3 训练方式
- 和预训练一样的 next-token prediction loss
- 但只对"回答部分"计算 loss（mask 掉 instruction 部分）
- 通常全参数微调，1–3 个 epoch
- 学习率远低于预训练（1e-5 ~ 5e-6）

---

## 阶段四：对齐训练（Alignment）

这是让模型"安全、有用、诚实"的关键阶段。当前有三条主流路线：

### 4.1 RLHF（基于人类反馈的强化学习）— 经典路线

```
Step 1: 收集人类偏好数据
   └── 同一 prompt 生成多个回答 → 人类标注哪个更好

Step 2: 训练奖励模型（Reward Model）
   └── 学习预测人类偏好

Step 3: 用 PPO 强化学习优化策略
   └── 策略模型（正在训练的 LLM）
   └── 奖励模型提供 reward 信号
   └── KL 惩罚约束不要偏离 SFT 模型太远
```

**问题**：PPO 复杂，需同时维护策略模型、参考模型、奖励模型和价值模型，训练不稳定。

### 4.2 DPO（直接偏好优化）— 简化路线

DPO 的核心洞察：**不需要显式训练奖励模型**，直接把偏好数据转化为分类 loss：

$$\mathcal{L}_{\text{DPO}} = -\log \sigma\left(\beta \log\frac{\pi_\theta(y_w|x)}{\pi_{\text{ref}}(y_w|x)} - \beta \log\frac{\pi_\theta(y_l|x)}{\pi_{\text{ref}}(y_l|x)}\right)$$

- $y_w$ = 被偏好的回答（winning）
- $y_l$ = 不被偏好的回答（losing）
- $\pi_\theta$ = 当前策略，$\pi_{\text{ref}}$ = 参考策略

**优势**：一步训练，无需奖励模型和 PPO，稳定高效。LLaMA 3、Qwen 2.5 等广泛使用。

### 4.3 GRPO（分组相对策略优化）— DeepSeek 的创新

DeepSeek-R1/V3/V4 的核心对齐算法：

```
传统 PPO:  需要「奖励模型」给出绝对分数
GRPO:      一组回答互相对比，计算相对优势

流程:
1. 对每个 prompt 生成 G 个回答（组，group）
2. 用规则奖励（数学正确性）或模型打分
3. 组内标准化 → 每个回答的「优势」= (自己得分 - 组均值) / 组标准差
4. 优化: 鼓励优势 > 0 的回答，抑制优势 < 0 的回答
```

**关键优势**：
- **无需独立的奖励模型**（用规则或策略模型自身打分）
- **组内相对比较比绝对打分更稳定**
- DeepSeek-R1 通过纯 GRPO 就激发出了强大的推理能力（无需大量 SFT 数据）

## 阶段五：后训练整合（Post-training Integration）

这是 DeepSeek-V4 引入的新范式，代表了 **2026 年前沿方向**：

### 传统方式（V3 及之前）
整个模型的 SFT + RL 一次性做完

### DeepSeek-V4 的两阶段后训练

```
阶段一：领域专家独立培养
  ├── 数学专家：SFT + GRPO（数学 CoT 数据）
  ├── 代码专家：SFT + GRPO（代码+测试用例）
  ├── 写作专家：SFT + DPO（写作偏好数据）
  └── 各领域独立训练，互不干扰

阶段二：统一模型整合
  └── On-policy distillation → 各专家知识蒸馏融合为单一模型
```

**收益**：各领域能力不会互相干扰（"遗忘"问题），最终模型在所有领域都达到专家级。

## 完整 Pipeline 一图总结

```
原始互联网数据
      │
      ▼
┌──────────────┐
│  数据准备     │  清洗、去重、分词、配比
└──────┬───────┘
       │
       ▼
┌──────────────┐
│  预训练       │  海量语料 · Next Token Prediction
│  (Pre-train) │  万卡集群 · 3D 混合并行 · 数月
└──────┬───────┘  产出：Base Model（基座模型）
       │
       ▼
┌──────────────┐
│  监督微调     │  高质量指令数据 · 学习对话格式
│  (SFT)       │  全参数微调 · 数天
└──────┬───────┘  产出：SFT Model（指令模型）
       │
       ▼
┌──────────────┐
│  对齐训练     │  RLHF / DPO / GRPO
│  (Alignment) │  偏好数据 · 数天到数周
└──────┬───────┘  产出：Aligned Model（对齐模型）
       │
       ▼
┌──────────────┐
│  后训练整合   │  领域专家独立训练 → On-policy 蒸馏融合
│  (Post-train)│  (DeepSeek-V4 新范式)
└──────┬───────┘  产出：Final Model
       │
       ▼
    部署上线 🚀
```

## 最新趋势（2026）

| 趋势 | 说明 |
|---|---|
| **MTP 训练** | 多 token 预测，样本效率更高 |
| **FP4 精度** | DeepSeek-V4 首次在 MoE expert 中用 FP4 |
| **Muon 优化器** | 替代 AdamW，更快收敛 |
| **两阶段后训练** | 领域专家独立培养 → 蒸馏融合 |
| **Auxiliary-Loss-Free MoE** | 去掉负载均衡辅助损失，不牺牲模型质量 |
| **合成数据占比提升** | 强模型生成 + 自动验证，缓解数据瓶颈 |
