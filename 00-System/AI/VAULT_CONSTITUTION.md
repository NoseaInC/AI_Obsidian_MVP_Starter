# Vault Constitution

这是知序所在 Vault 的工作空间规则。这些规则定义**内容应该写到哪里、写成什么、如何表达关系**。所有自动化（Agent、脚本）都必须遵守本文件。

## Vault 的目标

- 把外部资料稳定转化为**可追溯、可复习、可复用**的知识。
- 知识正文以 Markdown 为唯一真相；数据库只保存运行时状态。
- 每个结论都能回溯到来源（PDF 页码、对话消息、网页）。

## 一级目录职责

| 目录 | 职责 |
|---|---|
| `00-System` | 系统文件：Home、AI 规则、Templates、Bases、Canvases |
| `01-Inbox` | 未分类的临时输入，待处理 |
| `10-Sources` | 外部资料与出处索引（论文、书籍、课程、网页） |
| `20-Knowledge` | 正式知识：MOCs、Courses、Topics、Concepts |
| `30-Learning` | 学习过程：每日、每周记录与计划 |
| `40-Projects` | 项目专属内容，不与通用知识混用 |
| `80-Archive` | 归档 |
| `90-Local-Only` | 本地私有：提取文本、原始模型 JSON、中间产物，不同步 |

## 核心原则

1. **Markdown 是知识正文真相**。数据库不复制正文。
2. **目录表达稳定边界**。笔记类型决定目录归属，目录不被随意改写。
3. **链接表达知识关系**。使用有语义的 Wikilink。
4. **Properties 表达状态**。类型、状态、掌握度、复习单元等用 frontmatter 表达。
5. **MOC 表达人工知识结构**。MOC 是人工组织的入口，不是自动堆积的列表。
6. **Bases 表达动态视图**。动态查询用 Bases，不写死在笔记里。
7. **reviewed/core 默认受保护**。模型不得直接改写；只能生成更新建议。
8. **课程章节和复习单元必须分离**。章节是学习材料，Topic/Concept 才是可复习单元。
9. **项目过程不能自动当成通用知识**。项目专属内容留在 `40-Projects`。
10. **写入前必须检索已有内容**。先查再写，优先更新，不默认重复创建。

## 写入纪律

- 所有普通知识写入在进入事务前必须先产生结构化 WriteIntent。
- 发现同一知识主体时优先 update，不默认新建重复笔记。
- 无法确定归属时，宁可不写，不要猜。
